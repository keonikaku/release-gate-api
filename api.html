POST /changes

Create Change

Record a change in Draft. No rules run here. Drafting is not submitting. The gate evaluates REQ-1 when the change is submitted, which is what makes a rejection a decision about a submission rather than a schema error.

StatusMeaningBody
201Successful ResponseChangeRecord
422Validation ErrorHTTPValidationError

POST /changes/{change_id}/submit

Submit Change

Run REQ-1 against the change and move it to Submitted if it passes. A refusal is a 400 carrying every violation, not the first one. A change that is not in Draft cannot be submitted, and that is a 409 from REQ-2.

StatusMeaningBody
200Successful ResponseChangeRecord
400The gate refused the submission (REQ-1).RejectionResponse
404No such change.NotFoundResponse
409The change is not in Draft (REQ-2).TransitionErrorResponse
422Validation ErrorHTTPValidationError

POST /changes/{change_id}/transition

Transition Change

Move a change along the lifecycle (REQ-2). Draft to Submitted is not available here: it goes through `/submit`, so the validation cannot be stepped around.

StatusMeaningBody
200Successful ResponseChangeRecord
404No such change.NotFoundResponse
409The move is not on the lifecycle graph (REQ-2).TransitionErrorResponse
