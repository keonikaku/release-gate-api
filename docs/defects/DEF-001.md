# DEF-001

**Issue type:** Bug
**Summary:** Every write to the API returns 500 because the service opens its database in a directory that does not exist
**Status:** Closed

**Severity:** S1 Critical
**Reproducibility:** Always
**Environment:** non-live
**Components:** API, Persistence
**Labels:** api, wiring
**Affects version:** 0.1.0
**Fix version:** 0.1.0
**Existing case that should have caught it:** N/A

## Description

A configurable data directory was added to the service and defaulted to a path
that does not exist on the machine it runs on. Every request that touches stored
state fails. The health check keeps returning 200, so the service looks alive
while nothing works.

## Errant behaviour

`POST /changes` with a valid submission returns HTTP 500 and a plain text body of
`Internal Server Error`, with no JSON. The service log shows
`sqlite3.OperationalError: unable to open database file`.

## Expected behaviour

`POST /changes` with a valid submission returns 201 and the created change
record, with its identifier and a state of `draft`.

## Steps to reproduce

1. Start the service on a host where `/var/lib/release-gate` does not exist.
2. `GET /healthz`. It returns 200.
3. `POST /changes` with a valid submission body.
4. Observe 500 and a plain text body instead of 201 and a change record.
