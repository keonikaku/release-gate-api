DEF-002: The gate accepts a change whose implementation window ends before it starts Deferred

Failing testtests/integration/test_change_api.py::test_an_implementation_window_that_ends_before_it_starts_is_refused

Description

A change request carries an implementation start and an implementation end. Each is validated on its own: both have to be real timestamps with a timezone. Nothing compares them to each other, so a window that ends before it begins is accepted and the change passes the gate.

Errant behaviour

Submitting a change with implementation_start of 2026-08-02T02:00:00+00:00 and implementation_end of 2026-08-01T22:00:00+00:00, four hours earlier, returns 200 and moves the change to submitted. The gate raises no violation.

Expected behaviour

The submission is refused with 400 and a violation saying the implementation window ends before it starts. A change cannot finish being implemented before it has begun, and an implementation window is the field the on call requirement in REQ-1.6 is measured against, so a reversed one makes that check meaningless.

Steps to reproduce

1. POST /changes with a valid submission body, setting implementation_start to 2026-08-02T02:00:00+00:00 and implementation_end to 2026-08-01T22:00:00+00:00. 2. The change is created and returns 201. 3. POST /changes/{id}/submit. 4. Observe 200 and a state of submitted. Expected 400 and a violation.
